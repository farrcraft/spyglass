# Troubleshooting

## "Windows protected your PC", or "can't be opened" on macOS

The programs aren't code-signed, so your system warns about them. [The first run](install.md#the-first-run-on-windows-and-macos) says how to allow them.

## No Java found when extracting

Building game data needs Java, in the version the game needs: Java 25 for 26.3. The error lists every place spyglass looked. Install Java, such as [Eclipse Temurin](https://adoptium.net), or tell the extractor where yours is with `--java <path>`. See [Java](game-data.md#java).

## No bundles, or the wrong game version

Every spyglass program looks for game data in the same [bundles folder](game-data.md#where-bundles-go), and `--help` shows which folder that is. If you extracted into another folder, set the `SPYGLASS_BUNDLES` environment variable to it, or pass `--bundles <dir>`.

If you have several versions, pick one with `--game-version <id>`. The command uses a snapshot only when you name it.

## A warning that answers may differ from the game's

The bundle is for a game version this build of spyglass wasn't checked against. Its answers are probably right, but that isn't promised. A newer spyglass may support the version. `spyglass --version` lists the versions this one was checked against.

## Answers that don't match my world

Some things change what's in a world: a world type other than Default, data packs spyglass can't apply, mods, and chunks generated by an older game version. Run `spyglass world info` to see what spyglass found in your world, and see [when answers may differ](your-worlds.md#when-answers-may-differ).

## A structure is shown, but isn't there

It's probably a **candidate**: a place where the game tries to build the structure, but the ground decides whether it actually does. Turn on **Confirm with terrain** in the viewer, or pass `--confirm` to maps and searches, so spyglass checks the ground too. See [certain and candidate](answers.md#certain-and-candidate).

## Quotes on Windows

The examples in this guide put ids and queries in single quotes: `'#minecraft:village'`. That works in PowerShell. In the Command Prompt (cmd), use double quotes instead: `"#minecraft:village"`.

A query of several lines is easier to keep in a file and pass with `--query-file`.

## Features, loot or relief are slow to appear

spyglass finds features (such as dungeons) and loot by generating each chunk's decorations as the game does. That takes time, so they're drawn only when you zoom in. Relief shading and biomes at the surface need the terrain height of every column. All of them fill in as they're worked out.

## Something else

Report it on [GitHub](https://github.com/farrcraft/spyglass/issues). Include the output of `spyglass --version`, the command you ran or what the viewer showed, and what you expected.
