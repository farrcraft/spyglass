# m04. World saves

- Status: Completed
- Milestone: [04. World saves](../../roadmap/completed/04-world-saves.md)
- Started: 2026-10-25
- Completed: 2026-10-25

## Goal

Point spyglass at a local world save and get answers for that world: read its seed, version, preset and data packs, say plainly when spyglass can't predict it exactly, and run every locate query on it, from the player's position if asked. Covers all four of the milestone's exit criteria. It's the only plan for milestone 04.

## Facts established up front

Read from real saves on this machine on 2026-10-25: four 26.3 worlds (Modrinth, Fabric profile; one superflat, one upgraded from an earlier version) and three 1.21.x worlds (official launcher, one with 33 data packs). Dumped with a throwaway NBT script.

- **26.x layout.** `level.dat` (gzip NBT) has `Data.DataVersion` (5023), `Data.Version.{Id, Name, Series, Snapshot}` (`"26.3"`), `Data.LevelName`, `Data.WasModded`, `Data.DataPacks.{Enabled, Disabled}`, `Data.spawn.{pos, dimension}`, `Data.singleplayer_uuid` (4 ints) and `Data.version_history`. **No seed.** `data/minecraft/world_gen_settings.dat` has `data.seed`, `data.generate_structures`, `data.bonus_chest` and `data.dimensions.<id>.{type, generator}`, plus a top-level `DataVersion`. Regions are under `dimensions/minecraft/<overworld|the_nether|the_end>/region/`. The player is `players/data/<uuid>.dat` (`Pos` as three doubles, `Dimension`).
- **Pre-26 layout** (1.21.x). The seed and generators are in `level.dat` itself: `Data.WorldGenSettings.{seed, generate_features, bonus_chest, dimensions}`. Regions are in `region/`, `DIM-1/region/` and `DIM1/region/`. The single player is `Data.Player`.
- **No preset name is stored.** A Default world's overworld generator is `{type: minecraft:noise, settings: minecraft:overworld, biome_source: {type: minecraft:multi_noise, preset: minecraft:overworld}}`. A superflat world has `type: minecraft:flat` with its layers inline. So the preset is recognised by comparing each dimension's generator with the bundle's `worldgen/world_preset/*.json`.
- **`version_history` doesn't reveal upgrades.** The 26.3 world upgraded from an earlier version lists only `[5023]`. Old terrain shows only in each chunk's own `DataVersion`, in the region files.
- **Data packs.** `Enabled` lists `vanilla`, built-in feature packs, mod-provided packs (`fabric-convention-tags-v2`, with no files in the save) and `file/<name>` packs from `datapacks/` (zips or folders). The 1.21.8 world enables 33 packs.
- **The NBT reader exists.** `spyglass_data::nbt` (ADR 0013) reads gzip NBT with the full tag set. Region chunks are zlib by default (`region-file-compression=deflate`), which `flate2` already decompresses; LZ4 (an opt-in server setting) isn't supported by anything in the workspace.

## Approach

1. **`spyglass-world`** (depends on `spyglass-data`): `Save::read(dir)` reads both layouts into a `Save`: name, seed, data version and version name, `generate_structures`, each dimension's generator as JSON-like data, enabled and disabled data packs, `WasModded`, the world spawn and the single player's position and dimension. It does no worldgen and needs no bundle. A missing or unreadable file is an error naming the file and NBT path.
2. **Finding saves**: `saves_in_launchers()` lists saves from the official launcher's `saves/` and Modrinth's `profiles/*/saves/`, at each platform's default location. Any directory can also be given directly.
3. **Assessment** (in `spyglass`, which has the bundle): matching a save to a bundle and listing what makes it unpredictable, each as a typed warning:
   - no bundle with the save's data version (with the version name to extract);
   - the overworld's generator isn't the Default preset's (superflat, large biomes, amplified, single biome, debug, or custom), named when it matches another bundled preset;
   - data packs that may change worldgen: `file/` packs whose zip or folder holds `data/*/worldgen/` or `data/*/tags/worldgen/`; mod packs, which can't be inspected; feature packs, by name;
   - `generate_structures` false (structure answers are then empty);
   - chunks generated by older versions (per-chunk `DataVersion` below the save's), counted from the overworld's region files; their terrain and structures follow the old version.

   Unsupported generators and missing bundles are errors for locate queries; the other warnings are shown with every answer.

4. **Sessions from saves**: `spyglass::open_save(dir, bundles)` gives the save, its `World` and its warnings; `world.session(save.seed)` works as before. Locate answers are unchanged; front ends print the warnings with them.
5. **CLI**: `spyglass world list` (saves found in launchers), `spyglass world info <save>` (and `--json`), and `--world <save>` on every `locate` command in place of `--seed`, with `--from player` for the single player's position (overworld only, for now).
6. **Spot-checks in game**: extend `cargo xtask oracle locate` to run the dedicated server on a **copy** of a save, never the save itself, and compare with the API as in milestone 03. Plus a sanity check that each real save's spawn is in the 11 × 11 chunks around spyglass's spawn origin.

## Decisions

Agreed on 2026-10-25 (the draft's open questions, as recommended):

- **Other presets**: Large Biomes, Amplified and the rest are detected and reported as unsupported; supporting them is a follow-up.
- **Upgraded worlds**: count the chunks generated by older versions and warn. Reading the structure starts already stored in chunks is a later extension.
- **Data packs that count as changing worldgen**: `file/` packs with anything under `data/*/worldgen/` or `data/*/tags/worldgen/`; every mod-provided pack (its files aren't in the save); built-in feature packs, by name. Packs with only functions, advancements, loot tables and the like are ignored.
- **`--from player`**: single-player saves only.
