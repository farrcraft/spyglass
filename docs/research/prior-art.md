# Prior art

## Seed-map tools

- [cubiomes](https://github.com/cubitect/cubiomes) / [Cubiomes Viewer](https://github.com/cubitect/cubiomes-viewer): the standard open-source reference implementation for algorithms and features. Per-version tables are hand-ported, so support for new releases lags. That gap is spyglass's main reason to exist.
- **Chunkbase:** the most widely used web tool, closed-source. Useful as a feature checklist only.
- [slime_seed_finder](https://github.com/Badel2/slime_seed_finder): Rust seed finder with a WebAssembly biome viewer. Reference for search architecture and the 48→64-bit seed-extension trick.
- **Amidst:** older Java map viewer that ran against the user's own jar. Precedent for spyglass's local-extraction licensing approach.

## Rust Minecraft projects

- [Pumpkin](https://github.com/Pumpkin-MC/Pumpkin): Rust server whose `pumpkin-world` reportedly ports vanilla's noise router and density functions. Assess its parity and whether parts can be reused before writing terrain from scratch.
- [Azalea](https://github.com/azalea-rs/azalea) / [Valence](https://github.com/valence-rs/valence): templates for generating per-version code and data from the game.
- `fastanvil`: reads region files, which is useful for comparing against real saves.
- [Horizon](https://github.com/horizon-rust/horizon) (MIT): Java Edition 26.3 rewritten in Rust, generation included, checked against vanilla by its own differential harnesses. Its results are its claims, not an oracle; the leads below need spyglass's own measurement. Read 2026-11-11:
  - **`Math` by platform.** `horizon_core::jmath` models which methods HotSpot makes intrinsics: on x86-64, `sin`, `cos`, `tan`, `exp`, `log`, `log10` and `pow` are Intel's stubs, correctly rounded for all but about 0.1% of arguments; `atan2`, `atan`, `asin`, `acos` and `hypot` are fdlibm everywhere; on AArch64, `sin` and `cos` are fdlibm with fused multiply-adds. Microsoft's libm, which spyglass's Windows build calls, rounds `sin` and `cos` unlike Intel's for about 3% of arguments, which fits [ADR 0012](../adr/0012-java-trig-results-that-depend-on-the-platform.md)'s measurement. It has correctly rounded `sin`, `cos` and `log` in double-double arithmetic, and fdlibm 5.3 in Rust. Matching HotSpot this way could settle the float call sites that are unchecked today ([ADR 0068](../adr/0068-float-functions-and-more-clippy-lints.md)), and make spyglass's own builds agree across platforms.
  - **Decoration order.** `worldgen::decoration_order` replays vanilla's chunk scheduler around a standing player. It agrees with vanilla about as well as two vanilla runs agree with each other, which differ on about 6% of neighbouring chunk pairs, measured from JFR `minecraft.ChunkGeneration` events. [ADR 0056](../adr/0056-two-certainties-on-its-own-and-whatever-the-neighbours.md) treats the order as unknown; around the spawn at world creation, a third answer, as the game decorates then, may be possible.
  - **The port ledger** (`tools/port_ledger.py`) pairs each vanilla method with the Rust function whose doc comment names it, and its version-port report ranks changed methods that are ported but no harness covers. spyglass's doc comments name the game's methods the same way, so `cargo xtask version-diff --code` could list, per changed class, the files that cite it and the oracle tests that cover them.
  - **Data packs** change its generation: each enabled pack's worldgen files replace the bundle's, in pack order, and a fixture pack must match vanilla with the pack and differ from Horizon without it. spyglass only warns about them ([world-saves.md](../specs/world-saves.md)).
  - **Layers** are checked in CI (`tools/check_layers.py`). spyglass's crate order isn't checked: Cargo rejects only cycles.
- [MCToolKit](https://github.com/TwoPlayz/MCToolKit) (LGPL-3.0, so nothing is copied into spyglass): converts worlds between Java, Bedrock and Legacy Console, prunes chunks, edits NBT; "early and untested" at its first release (2026-10-30). Two features it suggests for saves: a layer of the chunks a save has generated (spyglass already reads every chunk's `DataVersion`; its pruner also reads `InhabitedTime`), and the save's own answer in generated chunks: their stored structure starts, and loot containers already opened.
